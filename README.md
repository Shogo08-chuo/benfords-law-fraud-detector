# Benford's Law Fraud Detector

ベンフォードの法則、ルールベースのリスクシグナル、生成AIを用いて、会計取引の確認優先度を整理するWebアプリケーションです。

> 本アプリケーションは監査・確認業務を支援するためのものです。不正の有無を判定・証明するものではありません。

## 概要

すべての会計取引を手作業で確認するには多くの時間がかかります。本アプリケーションは、取引金額と関連情報を分析し、優先的に確認すべき可能性がある取引を整理します。

ベンフォードの法則からの統計的な乖離に加え、承認上限直前の金額、同額取引の多発、月末集中、現金精算などの実務上のシグナルを組み合わせます。算出したリスクスコアをもとに、取引・ベンダー・部門の確認優先度を表示します。

## 主な機能

- CSV形式の会計データのアップロード、またはサンプルデータの利用
- `amount` 列がないCSVに対する金額列の自動検出
- ベンフォードの法則を用いた先頭桁分布の分析
- 複数の確認シグナルを用いた取引単位のリスクスコア算出
- 優先確認取引、ベンダー別・部門別のリスク傾向の表示
- Geminiによる確認観点の構造化
- Google Apps Scriptを利用した評価回答の記録

## 使い方

1. サンプルデータを選択するか、CSVファイルをアップロードします。
2. 全体の異常度と優先確認件数を確認します。
3. 優先確認リストと、各取引のリスク理由を確認します。
4. ベンダー別・部門別の集計から、確認が集中している領域を確認します。
5. AIによる確認観点を参考に、証憑や承認記録などの追加確認を行います。

### CSVの要件

- `amount` 列が存在する場合は、その列を金額として使用します。
- `amount` 列がない場合は、数値として読み取れる割合が高い最初の列を金額列として使用します。
- 空欄、非数値、0以下の金額は分析対象から除外します。
- 取引ID、日付、ベンダー、部門、承認上限は任意項目です。これらの情報がある場合、より詳細な確認シグナルを利用できます。

## リスクシグナル

リスクスコアは、以下のシグナルを組み合わせて算出します。

| シグナル | 内容 |
| --- | --- |
| ベンフォード偏差 | 理論分布から最も正方向に乖離した先頭桁と一致する取引 |
| 承認上限直前 | 金額が承認上限の90%以上かつ上限未満である取引 |
| キリの良い金額 | 金額が100の倍数である取引 |
| 同額取引の多発 | 同一金額の取引が4件以上ある場合 |
| 月末集中 | 取引日が月の26日以降である取引 |
| 現金精算 | 支払方法が現金精算である取引 |

## AIによる確認観点の整理

Geminiには統計結果、ベンダー別・部門別の集計、リスクの高い取引を入力します。プロンプトでは、次のルールを指定しています。

- 入力データに含まれる情報のみを根拠にする
- 不正を断定しない
- 正当な業務上の説明とリスク仮説を分けて記載する
- 各リスク仮説にデータ上の根拠を対応付ける
- 優先順位を付けた具体的な確認事項を提示する

AIの出力は、レビュー要約、優先確認事項、正当な業務上の説明候補、リスク仮説、追加で必要な情報で構成されます。

## 制約・注意事項

- ベンフォードの法則は、すべてのデータセットや業務に適用できるものではありません。
- データ件数が少ない場合、統計的な結果の信頼性が低くなることがあります。
- 定額料金、承認上限、サブスクリプション、月末処理などの正当な業務でも偏りが発生する場合があります。
- リスクスコアは確認の優先順位を示すシグナルであり、最終的な判断は担当者が行う必要があります。
- 機密情報・個人情報を含むデータは、適用されるセキュリティおよびプライバシー要件に従って取り扱ってください。
