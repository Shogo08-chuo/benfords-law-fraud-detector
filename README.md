# Benford's Law Fraud Detector

ベンフォードの法則と生成AIを組み合わせた、会計データの異常検知・調査仮説生成ツールです。
統計的な「違和感」を可視化するだけでなく、その結果を調査者が次に確認すべき観点へ落とし込むことを目的に実装しました。

## 作成物の概要

本アプリケーションは、CSV形式の会計・金額データに対してベンフォード分析を行い、先頭桁の分布が理論値からどの程度乖離しているかを確認するStreamlitアプリです。

従来のベンフォード分析は、分布の偏りを検知できても「なぜその偏りが起きているのか」「次に何を調べるべきか」の判断が分析者に依存しやすいという課題があります。そこで本プロジェクトでは、統計的検知とLLMによる意味理解支援を組み合わせ、会計不正・入力ミス・業務ルール由来の偏りなど、複数の仮説を比較しながら調査できる形にしました。

### 研究背景・設計思想

LLMは自然言語で柔軟に仮説を生成できる一方で、出力の根拠や判断過程が利用者から見えにくい、いわゆるブラックボックス性を持つという課題があります。特に監査や不正調査のように説明可能性が求められる領域では、LLMの出力をそのまま判断材料として扱うのではなく、確認可能な根拠と組み合わせて使う必要があります。

そこで本プロジェクトでは、ベンフォードの法則やχ²検定のように根拠を数値として確認できる統計的アプローチを組み合わせることで、LLMのブラックボックス性を補いながら、調査仮説の生成を支援することを目指しました。統計分析を「異常の検知」と「説明可能な根拠の提示」に用い、LLMを「不正判定器」ではなく、次に確認すべき観点を整理する支援役として位置付けています。

主な利用シーンは以下です。

- 経費精算や売上データなど、金額データに不自然な偏りがないか確認する
- ベンフォード分析の結果を、監査・調査で確認すべき観点に変換する
- LLMの提示スタイルが、調査者の判断や信頼感に与える影響を比較する

## 主な機能

- CSVアップロードによる金額データの読み込み
- デモデータ生成による正常データ・異常データの比較
- ベンフォードの法則に基づく先頭桁分布の算出
- χ²検定による統計的乖離の定量化
- Plotlyによる観測値と理論値の可視化
- Gemini APIによる調査仮説・確認観点の自動生成
- LLMの提示スタイル切り替え
  - 理解支援モード: 不正と断定せず、正当な理由と不正シナリオの両方を提示
  - 断定モード: リスクを強調する提示スタイル
- 調査時間の計測
- 評価フォームによる実験データ記録

## 自身が担当した役割

本リポジトリでは、以下の工程・実装を担当しました。

- 課題設定: ベンフォード分析の「検知できるが解釈が難しい」という課題を整理
- 分析ロジック実装: 先頭桁抽出、理論分布算出、χ²検定、異常桁の抽出
- UI実装: Streamlitによるデータ入力、タブ構成、グラフ表示、調査対象の絞り込み
- 生成AI連携: Gemini APIを用いた分析結果の自然言語化
- プロンプト設計: 不正断定を避ける理解支援モードと、比較用の断定モードを設計
- データ作成: 検証用の正常データ・異常データ生成スクリプトを作成
- 評価実験機能: 調査時間の計測とアンケート回答の送信処理を実装
- ドキュメント整備: 実行方法、技術構成、制約をREADMEに整理

### 使用モデル

Gemini APIの利用可能モデル一覧を取得し、`generateContent`に対応したモデルの中から以下の優先順位で選択しています。

1. `2.5-flash`を含むモデル
2. `1.5-flash`を含むモデル
3. 上記が利用できない場合は、取得できた対応モデル

これにより、実行環境で利用可能なGeminiモデルに合わせて動作するようにしています。

```text
        v

```

### 実装上のポイント

- 入力CSVに`amount`列がない場合は、利便性を優先して1列目を金額列として扱います。
- 欠損値や文字列は数値変換時に除外し、ベンフォード分析の対象は正の値のみに限定しています。
- 理論分布は`log10(1 + 1 / d)`で算出し、観測分布と比較しています。
- p値が0.05未満の場合に、統計的に有意な偏りとしてLLMによる解釈支援を表示します。
- LLM出力では、分析結果を不正の証明として扱わず、調査仮説として提示する設計にしています。
- APIキーはソースコードに直接書かず、Streamlit Secretsから読み込む構成にしています。

## 直面した課題と解決方法

| 課題 | 解決方法 |
| --- | --- |
| ベンフォード分析だけでは、偏りの意味を判断しづらい | Gemini APIに統計結果を渡し、正当な業務理由・不正シナリオ・次の確認事項を生成するようにした |
| LLMが「不正」と断定すると、調査者の判断を誘導してしまう | 理解支援モードでは、断定表現を避け、複数仮説を提示するプロンプトを設計した |
| 日本語ラベルを含むグラフで表示崩れが起きやすい | Matplotlib中心ではなくPlotlyを用い、ブラウザ上で見やすいインタラクティブな可視化にした |
| CSVの列名が利用者ごとに異なる | `amount`列がない場合は1列目を金額列として扱うことで、試用時の入力ハードルを下げた |
| 統計的な異常と実務上の不正を混同しやすい | READMEとアプリ内で、本ツールは不正を証明するものではなく調査補助であることを明記した |
| LLMの提示スタイルが判断に与える影響を検証したい | 理解支援モードと断定モードを切り替えられる設計にし、調査時間とアンケートを記録できるようにした |

## 実行方法

### 1. 依存関係のインストール

```bash
pip install -r requirements.txt
```

### 2. Gemini APIキーの設定

Streamlit SecretsにGemini APIキーを設定します。

```toml
GEMINI_API_KEY = "your_api_key"
```

### 3. アプリの起動

```bash
streamlit run app.py
```

起動後、サイドバーからCSVをアップロードするか、デモデータを生成して分析を実行できます。

## 制約と注意点

- ベンフォードの法則は、すべてのデータに有効な手法ではありません。
- データ件数が少ない場合や、価格設定・上限金額などの業務ルールが強いデータでは、自然な偏りが発生することがあります。
- 本ツールは不正を証明するものではなく、調査対象の優先順位付けと仮説生成を支援するものです。
- 実データを扱う場合は、個人情報・機密情報を含まない形に加工してから利用する必要があります。
- APIキーなどの認証情報は、READMEに直接記載しない運用が必要です。
