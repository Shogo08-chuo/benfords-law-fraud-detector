# Benford's Law Fraud Detector

ベンフォードの法則と生成AIを組み合わせて、会計データの「どこから確認するか」を決めるための Streamlit アプリです。

このアプリは不正を断定するものではありません。数字の偏り、承認上限直前、同額多発、月末集中などを手がかりに、優先確認対象を整理するためのツールです。

## できること

- CSV またはサンプルデータの読み込み
- ベンフォード分析による先頭数字の偏り確認
- リスクスコアによる優先確認リストの作成
- ベンダー別・部門別・理由別の集計表示
- Gemini API による確認観点の自然言語整理
- 調査時間計測と評価フォーム送信

## UI の考え方

画面は次の読み順で構成しています。

1. 結論
2. 次にやること
3. 注意事項
4. KPI
5. 数字の偏りチェック
6. 優先確認リスト
7. 集計と手法説明

統計値は残していますが、初見ユーザーが迷わないように主表示ではなく補足側に寄せています。

## 主な判定ロジック

このアプリでは、ベンフォード分析だけでなく、実務上の確認優先度に寄せる補助シグナルも使っています。

- 先頭数字の偏り
- 承認上限の直前
- キリの良い金額
- 同額取引の多発
- 月末集中
- 現金精算

これらを組み合わせて `risk_score` を算出し、確認順を出しています。

## セットアップ

### 1. 依存関係のインストール

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Secrets の設定

`.streamlit/secrets.toml` に設定します。

```toml
GEMINI_API_KEY = "your_api_key"
GAS_URL = "https://script.google.com/macros/s/xxx/exec"
```

- `GEMINI_API_KEY` は AI 機能に必要です
- `GAS_URL` は評価フォーム送信を使う場合のみ必要です

`secrets.toml` は Git にコミットしない運用にしています。

### 3. アプリの起動

```bash
streamlit run app.py
```

または仮想環境を明示する場合:

```bash
./.venv/bin/python -m streamlit run app.py
```

## CSV 取り込み仕様

- `amount` 列があればそれを使用します
- `amount` 列がない場合は、数値として読める列を自動検出します
- それも難しい場合は先頭列を金額列として扱います
- 空欄、非数値、0 以下の金額は分析対象から除外します

画面上では、使用した金額列、元件数、分析対象件数、除外件数を確認できます。

## 実装上のポイント

- ベンフォード理論分布は `log10(1 + 1 / d)` で算出
- 異常度は p値 と MAD を併用して判定
- 結果は「不正判定」ではなく「確認優先度」として提示
- AI 出力は補助情報として扱い、断定しない設計
- UI は初見ユーザー向けに、統計値より先に結論が見える構成

## 制約と注意点

- ベンフォードの法則はすべてのデータに有効ではありません
- 件数が少ないデータでは参考になりにくいです
- 承認上限、価格設定、定額契約、月末処理などでも偏りは発生します
- 本ツールは不正を証明するものではありません
- 実データを使う場合は、個人情報や機密情報の取り扱いに注意が必要です

## デプロイ運用の考え方

このリポジトリにはデプロイ設定ファイルは入っていません。  
そのため、GitHub に push しただけで本番反映されるかは、デプロイ先が GitHub リポジトリと自動連携しているか次第です。

一般論としては次の通りです。

- Streamlit Community Cloud で `main` ブランチを監視していれば、`main` への push で自動反映されます
- Render / Railway / Cloud Run などでも、GitHub 連携の自動デプロイ設定があれば反映されます
- ローカル実行だけ、または手動デプロイ運用なら、push だけでは反映されません
